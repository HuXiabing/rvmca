# pp 独立计时栈区与校准一致性修改规划

本文记录修改方案。现已完成源码修改、重新构建 `pp`、导出无伪指令反汇编以及本机功能验证；目标板周期验证尚未完成。实施结果见第 10 节。

## 1. 修改目标

为起始时间戳和计时临时寄存器分配明确的栈空间，使被测代码执行期间不需要为计时保留 `a5`、`a0` 或 `t6`。同时补齐空块校准路径的保存、恢复开销。

采用小范围修改：保留当前代码注入、15 条 `nop`、100 次采样以及 `minN - min0` 的结果计算方式。

“不保留计时寄存器”不等于所有寄存器和内存都能无约束地改写：`x0` 固定为零；`sp` 在进入收尾代码时必须恢复到约定位置；被测代码不能覆盖计时槽或调用上下文保存区。支持任意修改后不恢复的 `sp` 需要另外设计恢复机制，本次不包含。

## 2. 当前实现与参考项目

### 2.1 pp 已经具有时间戳落栈逻辑

当前 [src/profile.S](src/profile.S) 的起始序列为：

```asm
sd      t6, 1248(sp)     # 保存初始化后的 t6
rdcycle t6
sd      t6, 1240(sp)     # 保存起始时间戳
ld      t6, 1248(sp)     # 恢复被测代码需要的 t6
```

被测代码结束后，动态插入的 `rdcycle a0` 取得结束时间戳，再由收尾代码读取栈中的起始时间戳并计算差值。因此，当前计时逻辑实际上已不要求被测代码保留 `a5` 或 `t6`。

需要处理的问题是：

1. 两个槽使用的是现有 240 字节保存区中的空闲位置，布局缺少集中定义。
2. [src/pp.c](src/pp.c) 仍拒绝机器码 `0xc00027f3`，即 `rdcycle a5`。这条历史检查没有必要；它也从来不是对所有 `a5` 写操作的检查。
3. `profile0` 没有执行计时区间内的 `sd`、`ld`，造成校准与实测开销不一致。

### 2.2 trap-and-remap 的参考方式

已核对 `/home/huxiabing/Documents/trap-and-remap/run_test.S`：

- `store_cycle0` 定义为固定辅助内存地址 `0x7000020`。
- `code_end` 用 `rdcycle t4` 取得开始值并写入辅助内存，然后恢复 `t4`、`t2` 的约定初值。
- 结束模板用 `rdcycle t6` 取得结束值，之后重新加载开始值计算差值。

可借鉴的是“时间戳放内存、临时寄存器在进入被测块前恢复”的结构。pp 应恢复 `.init` 执行后的真实寄存器值，不能直接套用参考项目的固定寄存器初值；存储位置继续使用当前函数拥有的栈空间。

## 3. 新增独立的 16 字节计时区

将原来的寄存器保存帧从 **240 字节扩大到 256 字节**，工作区仍为 1024 字节。总分配量由 1264 字节变为 1280 字节，维持 16 字节对齐。

下面的偏移均相对于完成栈分配后、正常执行初始化和被测代码时的约定 `sp`：

| 相对 sp 的字节范围 | 用途 |
| --- | --- |
| `0 .. 1023` | 原有 1024 字节工作区 |
| `1024 .. 1239` | 原有寄存器保存槽，内部相对布局保持不变 |
| `1240 .. 1263` | 原保存帧的剩余 24 字节，作为填充，不再存计时数据 |
| `1264 .. 1271` | 新增：起始时间戳 |
| `1272 .. 1279` | 新增：进入计时前的 `t6` 值 |

新增 16 字节的目的是单独划定计时区；不是因为当前完全没有可用保存槽。原先的 `1240(sp)`、`1248(sp)` 将不再用于计时。

注意：被测块入口 `sp` 相对于调用者会比旧实现低 16 字节。按入口 `sp` 生成的相对访问继续使用原偏移；依赖旧运行栈绝对地址的输入需要重新检查。新增区域属于测量框架，不是供 `.init` 或被测块使用的工作区。

在 [src/count.h](src/count.h) 集中定义以下常量，避免汇编中重复手写偏移：

```c
#define PROFILE_SAVE_SIZE  256
#define PROFILE_WORK_SIZE 1024
#define PROFILE_START_SLOT (PROFILE_WORK_SIZE + PROFILE_SAVE_SIZE - 16)
#define PROFILE_T6_SLOT    (PROFILE_WORK_SIZE + PROFILE_SAVE_SIZE - 8)
```

保留现有 `__COUNT_START`、`__COUNT_END`、`__COUNT_END_CODE`，并确认后两者仍分别表示 `rdcycle a0` 与机器码 `0xc0002573`。

## 4. 修改 profileN

定位 [src/profile.S](src/profile.S) 的 `profileN`：

1. 将保存帧的分配、释放由 240 改为 `PROFILE_SAVE_SIZE`。
2. 将工作区的分配、释放统一使用 `PROFILE_WORK_SIZE`。
3. 保留原寄存器保存和恢复槽相对于保存帧起点的偏移。
4. 将计时槽迁移到两个新常量指定的位置。

预期核心序列如下，省略原有上下文保存、初始化和恢复代码：

```asm
# 已分配保存帧和工作区，并执行完 .init。
fence
sd      t6, PROFILE_T6_SLOT(sp)
__COUNT_START
sd      t6, PROFILE_START_SLOT(sp)
ld      t6, PROFILE_T6_SLOT(sp)

.rept PIPELINE_DEPTH
    nop
.endr

profile_insn_start:
# 被测代码；C 在有效代码末尾插入 __COUNT_END_CODE。
# 其余预留 nop 仍按原路径执行，但位于结束读数之后。

fence
ld      t6, PROFILE_START_SLOT(sp)
sub     a0, a0, t6
# 恢复调用上下文、sp，然后返回。
```

被测代码可以读取或改写 `a5`、`t6`、`a0`。`t6` 在进入被测块前恢复为 `.init` 留下的值；结束读数覆盖 `a0` 时，被测块已经结束，不影响其执行所需的输入。

## 5. 同步修改 profile0

不能只修改 `profileN`，否则原有校准差异仍然存在。

`profile0` 在读取开始时间之前分配同样的 256 字节保存帧和 1024 字节工作区，使用相同偏移保存原 `t6` 和起始时间戳。其计时区间必须与 `profileN` 一致，唯一省略的是被测代码：

```asm
profile0:
    addi    sp, sp, -PROFILE_SAVE_SIZE
    addi    sp, sp, -PROFILE_WORK_SIZE
    fence
    sd      t6, PROFILE_T6_SLOT(sp)
    __COUNT_START
    sd      t6, PROFILE_START_SLOT(sp)
    ld      t6, PROFILE_T6_SLOT(sp)

    .rept PIPELINE_DEPTH
        nop
    .endr

    __COUNT_END
    fence
    ld      t6, PROFILE_START_SLOT(sp)
    sub     a0, a0, t6
    addi    sp, sp, PROFILE_WORK_SIZE
    addi    sp, sp, PROFILE_SAVE_SIZE
    ret
```

`profile0` 只改写 ABI 允许其改写的临时寄存器及返回值寄存器，不必复制 `profileN` 为任意被测代码保存的全部寄存器。

在汇编中抽取公共计时开始宏，包含 `fence → 保存原 t6 → 读取开始值 → 保存开始值 → 恢复 t6 → 15 条 nop`，让两条路径共用。结束后的 `fence → 加载开始值 → 相减` 也可抽取为宏。动态插入的结束指令仍保留原有方式。

校准区间和实测区间都包含 `sd`、`ld` 及相同数量的 `nop`；栈分配、保存原 `t6` 和最终相减均在两次读数之外。指令一致是必要条件，硬件上的残差仍需实测，不能预设固定减少 2 cycles。

## 6. 删除 a5 的历史检查

在 [src/pp.c](src/pp.c) 删除以下分支：

```c
if (encode == 0xc00027f3) {
    perror("Do not use the profiling instruction 'rdcycle a5'.\n");
    return EXIT_FAILURE;
}
```

不新增针对 `a0`、`a5` 或 `t6` 的计时寄存器禁用规则。保留现有 JAL/JALR 截断和结束时间戳注入逻辑。

包含 `rdcycle a5` 的被测块将作为普通输入执行，其自身读计数器的开销属于被测代码。

## 7. sp 和内存约束

本方案依靠 `sp` 寻址，必须明确以下前提：

- `.init` 结束后，`sp` 必须处于测量框架约定的位置。
- 被测块可以临时调整 `sp`，但进入测量收尾时必须恢复原值。
- `.init` 和被测代码不能覆盖新增计时槽或原有上下文保存槽；通过其他寄存器间接访问这些地址同样不允许。
- 不能把“去掉 a5 检查”解释为可以任意破坏 `ra`、`sp`、保存槽或改变控制流。

执行前检查现有输入生成器是否满足上述条件。初始实施不修改已有独立变更的 `src/rvmca/trans/prof.py`；若检查发现它会生成不满足条件的输入，应记录并明确跳过或另行补充生成约束，不将这些输入计入本方案的验证通过范围。

## 9. 验证与验收

### 9.1 编译和无伪指令反汇编

强制重新构建，并重新导出反汇编：

```bash
make -B pp
riscv64-unknown-linux-gnu-objdump -d -M no-aliases pp > pp_dis_no_aliases.txt
```

核对：

- 两条路径的栈分配和释放配对，入口和出口保持 16 字节对齐。
- 时间戳使用 `1264(sp)`，原 `t6` 使用 `1272(sp)`。
- 起始、结束读数显示为真实指令 `csrrs t6,cycle,zero` 和 `csrrs a0,cycle,zero`。
- 除被测代码外，两次读数之间均为相同的 `sd`、`ld` 和 15 条 `addi zero,zero,0`。
- 正常执行初始化后、进入被测代码前，`t6` 已恢复；结束读数后再加载开始值。
- 结束指令注入仍能正确覆盖有效代码后的槽位，空块与最大长度输入均检查边界。

### 9.2 功能回归

使用小型输入或临时验证夹具检查以下行为；需要时单独生成验证版本，不为这些检查改变正式输出格式：

1. 空 `.init`、空被测块：完整执行并返回。
2. `.init` 为 `t6` 设置已知值，被测块读取它并将结果写入工作区：确认被测块看见的是初始化值，而非时间戳。
3. 被测块写入 `t6`、`a5`、`a0`：确认可执行，结束后的原始周期差有效；通过反汇编确认起始值从专用槽读取。
4. 被测块包含 `rdcycle a5`：不再因旧检查直接退出。
5. 被测块临时调整并恢复 `sp`，以及正常访问工作区：确认返回与上下文恢复正常。
6. 选取现有整数、浮点和访存块回归，确认输出字段与采样流程保持兼容。

QEMU 可用于功能执行验证，不能据此认定目标处理器的周期开销已经匹配。

### 9.3 目标板周期验证

在同一目标板、相同配置下记录修改前后结果，多次运行空初始化和空被测块：

- 原始实测、校准读数应接近，扣除后的空块周期应接近 0。
- 记录残差范围，不以每次严格等于 0 为要求；若存在稳定偏差，继续检查前序访存和微架构状态影响。
- 再运行少量 `nop` 与典型块，确认结果变化合理。

验收条件为：计时不占用被测块期间的通用数据寄存器、专用槽不越界、校准指令序列匹配、功能回归通过，并给出目标板的实际空块残差。尚未完成目标板验证时，应明确标记周期一致性未验收。

## 10. 实施与验证记录

已按上述布局修改 `count.h`、`profile.S`、`pp.c` 和 `Makefile`。`profile0` 与 `profileN` 共用 `profile_count_start` 和 `profile_count_result` 汇编宏，旧的 `rdcycle a5` 拒绝分支已删除。

边界检查另发现：旧代码在被测块恰好为 `MAX_INSN` 条时，会将结束读数写到随后的 `fence` 上。现将被测区预留量改为 `MAX_INSN + 1` 条，最后一槽专供注入结束读数，用户输入上限仍为 1024 条。

已完成的验证：

- `make -B pp` 成功；链接器仍提示现有可写可执行代码段的 RWX 属性。
- 已更新 `pp_dis_no_aliases.txt`，自动对比确认两条路径从开始读数到被测块入口的机器码相同：开始读数、保存时间戳、恢复 `t6`、15 条 `nop`。
- 确认新槽偏移为 `1264(sp)`、`1272(sp)`，最大长度的结束读数槽后仍保留 `fence`。
- QEMU 下通过 9 组临时构造用例：空块、初始化后 `t6` 值的读取验证及计时寄存器写入、`rdcycle a5`、临时调整并恢复 `sp`、整数计算、浮点计算、调用上下文寄存器改写、1024 条初始化及被测指令、1025 条超限拒绝。正常用例均完成 100 次采样。
- 用例中的 `t6` 恢复、工作区读写和整数计算通过条件分支及失败时触发 `ebreak` 验证结果，而非仅检查进程成功退出。
- 头文件依赖检查确认修改 `count.h` 会触发重新构建；代码差异通过 `git diff --check`。

本次功能回归使用的是满足第 7 节约束的构造输入，没有据此认证所有现有生成器输出。检查 `src/rvmca/trans/prof.py` 时未发现本方案新槽位的显式保护；这不足以证明所有生成输入均安全，批量测量前仍须检查 `sp` 恢复和保存区不重叠条件。

本机为 x86_64，QEMU 结果只用于功能验证。尚无目标板的修改前后空块周期数据，硬件周期一致性仍待验收。

## 11. 保存版本时的最终计时序列

后续调整已将原 `t6` 的保存移到起始 `fence` 之前，并在 15 条 `nop` 后增加 `fence`。当前源码以本节为准：

```asm
sd      t6, PROFILE_T6_SLOT(sp)
fence
__COUNT_START
sd      t6, PROFILE_START_SLOT(sp)
ld      t6, PROFILE_T6_SLOT(sp)
.rept PIPELINE_DEPTH
    nop
.endr
fence
```

两条路径共用此宏，新增的末尾 `fence` 位于计时区间内。被测块末尾仍直接注入 `rdcycle a0`，没有另外插入读数前的屏障；`profile_count_result` 中的 `fence` 位于结束读数之后。

保存版本前已重新编译、更新无伪指令反汇编，并用 QEMU 再次验证空块、`rdcycle a5` 和 1024 条指令输入，均完成 100 次采样。目标板周期验证状态不变。
